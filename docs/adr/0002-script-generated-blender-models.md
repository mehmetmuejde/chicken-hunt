# 2. Generate 3D models with scripted Blender and load them as glTF

## Status

Accepted

## Context

The first-person weapons (shotgun, MG 42) fill a large part of the screen, so building them from
Babylon.js primitives in code looks too crude. Options considered: free CC0 asset packs (no MG 42,
FBX/Blend only), paid or local AI text/image-to-3D generation (paid APIs or too heavy to run
locally), and modelling in Blender. Blender 5.2 is installed locally.

## Decision

Weapon models are generated by a Python script that runs Blender headless
(`blender/build_weapons.py`). The script writes the editable source file `blender/weapons.blend` and
exports one binary glTF per weapon into `public/models/`. The game loads them with
`@babylonjs/loaders` (glTF 2.0 only).

Model conventions: metres, Blender +Y is the barrel direction, +Z is up. Moving parts are separate
objects and the muzzle and ports are empties, all named `<Prefix>_<Part>` (e.g. `Shotgun_Pump`,
`MG42_Cover`, `Shotgun_Muzzle`), so the game can find and animate them. Animations are done in code,
not baked into the files. The loaded PBR materials are converted to Standard materials at runtime to
match the scene's lighting, which has no environment map.

## Consequences

- Models are reproducible and reviewable as code; regenerating them overwrites `weapons.blend` and the
  `.glb` files, so manual edits in Blender must be moved into the script or they are lost.
- Adds the runtime dependency `@babylonjs/loaders`; the glTF loader pulls in lazily loaded chunks
  (PBR shaders etc.), which grows the build output.
- Renaming a node in the script breaks the lookup in `src/viewmodel.ts`.
